Install & permissions

For a bundled worker, install the package from GitHub and import the functions you need:

Terminal
npm install github:x7k6/webrequest-mv3
worker.js · bundled entry point
import { compileRule, createRuleStore, observe, provideAuth }
  from 'webrequest-mv3';

Without a bundler, copy extension/lib/ beside your worker and change the import path to ./lib/index.js. Set background.type to module.

Rule installation
For the permission model in this guide, add declarativeNetRequestWithHostAccess and appropriate host_permissions for target hosts and, for subresources, their initiators.
Observation and auth
Declare webRequest plus the relevant host access. To answer auth challenges, also add webRequestAuthProvider. Register listeners at worker module scope, before any await.

compileRule(spec, scope?)

Returns one native DNR rule without installing it. Use it to inspect the translation or generate rules in a build step.

Example · block a POST
const rule = compileRule({
  id: 100,
  event: 'onBeforeRequest',
  filter: { urls: ['https://example.org/beacon/*'] },
  when: { requestMethods: ['post'] },
  response: { cancel: true },
});
id and priority
Use a positive integer ID. Priority defaults to 1. Conflicts follow Chrome’s rule evaluation order ↗.
filter and when
Supply at least one URL pattern. Optionally limit resource types, lowercase requestMethods, initiatorDomains (including subdomains), or domainType (firstParty / thirdParty). Conditions must all be satisfied.
event and response
At onBeforeRequest, choose { cancel: true } or { redirectUrl: 'https://…' } with an absolute HTTP(S) destination. For request or response header stages, supply header edits.

URL matching

filter.urls lists alternatives. For example, *://*.example.org/api/* matches HTTP or HTTPS on the apex or a subdomain. The path and query are case-sensitive. An omitted types includes all supported types, even main-frame navigation.

Use ASCII hostnames (Punycode for IDNs). Ports in requests are accepted, but explicit ports and literal IPv6 hosts in patterns are not. <all_urls> covers HTTP(S), WS(S), FTP, and file schemes, subject to Chrome’s interception and access permissions.

Each spec compiles to one anchored RE2 filter against the serialized URL. Percent-encoded paths can differ from native webRequest matching. For large lists, consider native static rules using urlFilter or domain conditions.

createRuleStore(options)

Reserve an inclusive ID range in one ruleset. Call store.replace(specs) with every rule that should remain in that range. Await the promise to confirm installation.

worker.js · dynamic rules
const store = createRuleStore({ firstId: 100, lastId: 199 });

chrome.runtime.onInstalled.addListener(() => {
  store.replace([{
    id: 100, event: 'onBeforeRequest',
    filter: { urls: ['https://example.org/beacon/*'] },
    response: { cancel: true },
  }]).catch(console.error);
});

Dynamic rules (default) survive browser restarts and extension updates. Session rules survive worker suspension but clear on browser shutdown or extension update. Set scope: 'session' to use a nonnegative filter.tabId.

One writer per range. Reuse one store instance to serialize replacements. Omitting an ID removes it; await store.replace([]) clears the range. Rules outside it remain intact. A rejected atomic replacement leaves the previous rules in place.

Header edits

Use onBeforeSendHeaders with requestHeaders for outgoing requests, or onHeadersReceived with responseHeaders for incoming responses. Describe individual changes rather than returning the full header list.

Rule spec · set a response header
const headerRule = {
  id: 101, event: 'onHeadersReceived',
  filter: { urls: ['https://example.org/api/*'] },
  response: { responseHeaders: [
    { header: 'X-Demo', operation: 'set', value: 'MV3' }
  ] },
};

Use set or append with a string value. Use remove without a value. Chrome limits which request headers may be appended.

observe(name, listener, filter, options?)

Registers a native nonblocking webRequest listener synchronously and returns an unsubscribe function. Pass event-specific options, such as responseHeaders on onCompleted, to receive additional details. Observation cannot change an in-flight request.

worker.js · observe errors
const unsubscribe = observe('onErrorOccurred',
  ({ error }) => console.debug(error),
  { urls: ['https://example.org/*'] }
);

provideAuth(filter, provider)

Returns an unsubscribe function and bridges a sync or async provider to Chrome’s auth callback. Return credentials for a matching challenge, { cancel: true } to stop it, or undefined to let Chrome handle it. A thrown error, rejection, or malformed response cancels the challenge.

worker.js · scoped auth provider
provideAuth({ urls: ['https://intranet.example.org/*'] },
  async details => {
    if (details.isProxy || details.realm !== 'intranet' ||
        details.challenger.host !== 'intranet.example.org' ||
        details.challenger.port !== 443) return;
    return lookupForChallenge(details);
  });

Implement lookupForChallenge in your application. Bound retries and return credentials as { authCredentials: { username, password } }.
